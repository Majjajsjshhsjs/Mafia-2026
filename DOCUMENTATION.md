## 🎯 О проекте

**Mafia-2026** — веб-проект для онлайн-игры в «Мафию». Предполагаемая модель приложения разделяет клиентский интерфейс в браузере и сервер, который управляет игровым состоянием и правилами.

Игроки присоединяются к комнате, получают скрытые роли, действуют ночью и обсуждают результаты днём. Цель зависит от команды: мафия стремится получить численное преимущество, а город — выявить и устранить всех мафиози.

| Параметр | Значение |
|---|---|
| Название проекта | Mafia-2026 |
| Версия документации | 1.0 |
| Язык реализации | JavaScript |
| Среда выполнения | Node.js 16 или новее (согласно исходному описанию) |
| Статус | Активная разработка — согласно исходному описанию |
| Репозиторий | [GitHub](https://github.com/Majjajsjshhsjs/Mafia-2026) |

Указанные сведения не заменяют проверку актуального `package.json` и исходного кода.

## 🧩 Компоненты

### `server.js`

Предполагаемая точка входа серверной части. В зависимости от реализации может отвечать за:

- запуск HTTP-сервера;
- обработку входящих запросов;
- выдачу статических файлов из `public/`;
- подключение модулей игровой логики;
- обработку подключений и действий игроков.

### `public/`

Клиентская часть приложения:

- `index.html` — основная HTML-разметка;
- `css/` — оформление и адаптивные стили;
- `js/` — клиентские события, отправка действий и отображение игрового состояния.

### `src/game/`

Модули игровой логики, если они присутствуют в текущей версии:

- `roles.js` — определения ролей и их возможностей;
- `phases.js` — переходы между игровыми фазами;
- `state.js` — состояние партии, список игроков и результаты действий.

### `package.json`

Содержит метаданные проекта, зависимости и доступные npm-скрипты. Перед запуском проверьте именно этот файл: не все проекты имеют скрипт `start`.

### `.env`

Локальные настройки среды. Не добавляйте в репозиторий реальные пароли, токены или секреты.

## 🚀 Установка и запуск

### Требования

- Node.js версии, совместимой с проектом (в исходном описании указана версия 16 или новее).
- npm, обычно устанавливаемый вместе с Node.js.
- Git — если вы клонируете репозиторий.

Для нового развёртывания рекомендуется использовать поддерживаемую LTS-версию Node.js, совместимую с зависимостями проекта.

### 1. Клонируйте репозиторий

```bash
git clone https://github.com/Majjajsjshhsjs/Mafia-2026.git
cd Mafia-2026
```

### 2. Установите зависимости

```bash
npm install
```

### 3. Настройте окружение

Если приложение требует переменные окружения, создайте локальный `.env` на основе документации проекта или примера `.env.example`, если он есть. Не копируйте вымышленные значения секретов в рабочую среду.

### 4. Запустите приложение

Сначала посмотрите доступные скрипты:

```bash
npm run
```

Если в `package.json` определён скрипт `start`, запустите:

```bash
npm start
```

Если такого скрипта нет, изучите `package.json` и инструкции в репозитории. Запуск через `node server.js` подходит только в том случае, если приложение действительно использует этот файл как точку входа.

### 5. Откройте приложение

Перейдите по адресу и порту, указанным в выводе сервера или конфигурации. Не предполагайте, что приложение всегда использует порт `3000`.

## 🎮 Игровой процесс

Ниже описан классический вариант правил «Мафии». Фактические правила Mafia-2026 определяются кодом проекта.

1. **Лобби.** Игроки присоединяются к комнате.
2. **Раздача ролей.** Каждому участнику назначается скрытая роль.
3. **Ночь.** Роли с ночными действиями выбирают цели или применяют способности.
4. **День.** Игрокам сообщают доступные сведения; участники обсуждают подозрения.
5. **Голосование.** Город выбирает игрока для исключения по правилам партии.
6. **Проверка победы.** Если условие победы не выполнено, начинается следующий раунд.

### Условия победы в классическом варианте

- **Город:** все мафиози устранены.
- **Мафия:** мафия достигает численного равенства с оставшимися противниками или другого порога, установленного правилами игры.

Точный порядок разрешения одновременных действий, ничьих и особых случаев необходимо сверить с реализацией.

## 🏗️ Архитектура

Предполагаемое разделение ответственности:

```text
Браузер (public/)
      │
      │ HTTP и/или другой реализованный транспорт
      ▼
Сервер (server.js)
      │
      ▼
Игровая логика (src/game/)
      ├── роли
      ├── фазы
      └── состояние партии
```

Фактический транспорт — HTTP, WebSocket или библиотека поверх него — должен определяться по коду и зависимостям. Диаграмма не означает, что WebSocket уже реализован.

### Рекомендуемые принципы

1. **Сервер авторитетен.** Клиент не должен самостоятельно определять роли, результаты ночных действий или победителя.
2. **Проверяйте действия.** Сервер должен проверять, существует ли игрок, жив ли он, наступила ли нужная фаза и разрешено ли действие этой роли.
3. **Скрывайте секретную информацию.** Игрок должен получать только те сведения о ролях и действиях, которые разрешены правилами.
4. **Разделяйте ответственность.** Сетевой код, игровую механику и пользовательский интерфейс удобнее поддерживать независимо.
5. **Обрабатывайте отключения.** Определите, что происходит при выходе игрока, повторном подключении и потере связи.

Это рекомендации по проектированию; они не гарантируют, что все перечисленные механизмы уже реализованы.

## 🔐 Безопасность

Для онлайн-игры особенно важно не раскрывать скрытые роли и не доверять данным браузера.

- Не публикуйте `.env` и другие файлы с секретами.
- Используйте случайные, уникальные секреты для соответствующих механизмов защиты.
- Проверяйте все действия на сервере, а не только в клиентском JavaScript.
- Не отправляйте клиентам скрытые роли или ночные решения, которые им не положено знать.
- Ограничивайте частоту повторяющихся запросов и голосов.
- Валидируйте идентификаторы комнат, игроков и цели действий.
- Не храните реальные пароли в открытом виде.
- Обновляйте зависимости и проверяйте их происхождение.

Этот раздел содержит рекомендации, а не аудит безопасности существующего кода.

## ❓ Часто задаваемые вопросы

### Что такое Mafia-2026?

Веб-проект, предназначенный для игры в «Мафию» через браузер.

### Какой порт используется по умолчанию?

В исходном описании приведён пример `3000`, но фактический порт нужно проверить в конфигурации и коде сервера.

### Можно ли играть по локальной сети?

Это возможно, если сервер слушает подходящий сетевой интерфейс, а настройки сети и межсетевого экрана разрешают подключения. Убедитесь, что приложение безопасно для выбранной среды.

### Где хранится состояние игры?

В описании указан модуль `src/game/state.js`, однако фактическое место хранения и срок жизни данных нужно проверить по исходному коду. Если состояние хранится только в памяти процесса, оно обычно теряется при перезапуске сервера.

### Нужна ли база данных?

Это зависит от функций приложения. Для временного состояния партии база данных может не требоваться; аккаунты, история игр и постоянная статистика обычно требуют постоянного хранилища.

### Как добавить новую роль?

Изучите `roles.js`, обработку фаз, серверную проверку действий и клиентский интерфейс. Подробный порядок приведён в разделе [«Разработка»](#-разработка).

### Можно ли играть с телефона?

Это зависит от адаптивности интерфейса. Проверьте страницы и стили в `public/` на небольших экранах.

### Какие браузеры поддерживаются?

Поддержка зависит от используемых веб-API и тестирования. Проверяйте приложение в актуальных версиях браузеров, которые планируете поддерживать.
